# PocketHLE 操作方便性設計審查 — 2026-11-08

> **整合狀態（2026-11-08）**：本審查來自平行的 Codex 工作區。已完成：發現 1（重新匯入保留進度，f4d2ada）、發現 2 的網頁同步等待（c15813b）、發現 3 的網頁輸入訂閱清理與失焦放開按鍵（c15813b）、發現 4 的網頁真暫停（116d520，核心 `guest_clock`）、發現 5 的網頁按鍵隱藏（15b66aa）、發現 8 的網頁遊戲庫搜尋與最近遊玩（c15813b）。其餘（三平台一致選單、Windows／Android 暫停、每遊戲按鍵配置、設定分層、可存取性）尚未做。


本次檢查 Windows egui、Web、Android 的前端原始碼，並參照上一輪 EQ 實測畫面與操作紀錄，以及 PPSSPP、RetroArch 官方文件。這是設計與程式路徑審查，沒有重新執行遊戲、使用者研究或新一輪觸控量測；沒有變更執行程式或操作 Git。以下將可確認的程式行為、既有實測現象與建議分開。

目前已具備容易入門的基礎：原始封裝匯入、遊戲卡片、畫面旋轉、跨平台進度 ZIP、Android 實體手把及鍵盤輸入、Web 操作說明與虛擬鍵盤。最大的改善空間在退出與進度的語意、觸控可靠性，以及常用操作的入口一致性。建議先處理這些，再調整卡片外觀。

## 主要發現（依優先順序）

### 1. P1：重新匯入同一遊戲可能讓使用者失去進度

`crates/pocket-library/src/lib.rs:799` 的 CAB 匯入註解明確說明同 id 取代整個資料夾；`fresh_game_dir`（約 1711 行）將舊資料夾移開，而 `import_direct` 成功提交後刪除舊副本（約 1674 行）。失敗回復機制有保護，但成功重裝不是保留進度的更新流程。前端目前的「匯入遊戲」沒有清楚呈現這個差別。

剛完成的音效專用補丁有保留進度契約，不能據此推論所有 ZIP／CAB 重匯入也安全。

建議：共用匯入預檢回傳「新安裝／更新既有遊戲／音效補充」。更新預設保留 `saves/`、registry snapshot 與使用者設定；需要清除時才提供另列的「重新安裝並清除進度」。一般安全更新不加確認對話框。用暫存目錄驗證後才替換安裝資料，保留失敗回復。

驗收：同遊戲重匯入後 SAV、CSS、registry 及設定不變；更新失敗也不變；明確清除才刪除進度。

### 2. P1：返回遊戲庫、遊戲存檔、進度備份的語意混在一起

Windows `app.rs:939` 的 Back to library 送出 Stop；Android `GameActivity.kt:256` 的 Back 要求停止 session；Web `index.html:1639` 同步檔案系統後 reload。這些動作不能保證遊戲已把尚在記憶體中的角色資料寫入檔案。Web 的「下載存檔」是匯出現有 saves，並非執行遊戲內存檔，也不是即時存檔。

Web `syncFs`（657 行）另有可確認的等待問題：已有同步進行時，後續呼叫設置 `syncAgain` 後立即 resolve。此時返回遊戲庫的 await 不代表待排程的同步完成，reload 與尚未完成的寫入存在競態。這是程式路徑風險，這輪未做中斷寫入重現。

建議：改用明確的「遊戲進度」「備份進度 ZIP」「返回遊戲庫」名稱。顯示已驗證寫入的時間，不把同步時間當作角色存檔時間。返回前等待真正的寫入完成；失敗時保留遊戲與可重試入口。遊戲沒有共通存檔 API 時，提示先使用遊戲內存檔，不提供假的「儲存並退出」。

驗收：同步排隊期間返回不提前 reload；儲存錯誤不顯示成功；備份名稱與說明不暗示保存目前執行狀態。

### 3. P1：輸入可靠性要先於新增虛擬按鍵功能

既有 Android EQ 測試曾出現 150 ms 注入點擊漏接、500 ms 按住才成功的情況；上一輪遊戲庫啟動也曾需要重試。兩者分別涉及主機 UI 和客體輸入，不能直接判定為同一個缺陷或實際手機普遍故障。使用者感受到的問題則相同：不知道有沒有按到。

Web 有另外可確認的生命週期問題：`start` 每次呼叫 `attachInput`（約 950 行），後者向 window、canvas、虛擬按鍵新增監聽器，未提供清理；每次 start 也增加一個未清除的同步 interval（1012 行）。遊戲自行結束後同頁再啟動會累積處理器，舊 width／height 閉包也可能保留。`press` 沒有重複 KeyDown 防護；一般 window 鍵盤處理器亦缺少遊戲／文字輸入焦點判斷。頁面隱藏時只同步資料，沒有統一釋放按鍵的處理。

建議：每個 session 擁有唯一的輸入訂閱、計時器與清理函式，結束／失焦時取消延遲 KeyUp、釋放 held keys 和 stylus。鍵盤、虛擬按鍵、手把的持有狀態分開追蹤，最後合併為客體按鍵狀態。另行量測 Android 短觸控傳遞，避免用固定長按掩蓋原因。

驗收：同頁重開十次後每個動作仍只有一次邊緣；240×320 與 WVGA 遊戲互切座標正確；切換分頁及視窗後無卡鍵；文字欄位不被遊戲快捷鍵攔截。Android 以多種短點時間與不同負載量測接收情況，標示失敗發生在哪一層。

### 4. P1：缺少三平台一致的遊戲中選單與真正暫停

Windows 遊玩頁仍稱 Run output；常用操作是 rotation、兩種 fullscreen、Back。Android toolbar 主要是返回與全螢幕。Web 有鍵盤、操作說明、旋轉及下載存檔。Windows `InputCommand` 只有 Input 和 Stop；Android `onPause` 釋放輸入並停止音訊，沒有在這條路徑暫停 native worker。停止聲音不能代表遊戲暫停。

參考 RetroArch 的 Quick Menu：將繼續、操作設定與退出集中在遊玩中可開啟的入口。官方也明確將它描述為暫停選單。[官方文件](https://docs.libretro.com/guides/quick-menu/)

建議：三平台共用同一套選單內容與能力狀態：繼續遊戲、操作方式、顯示、音量、備份進度、返回遊戲庫。桌面用可重新配置的快捷鍵，Android Back 先開選單，Web 提供可觸控的入口。必須先建立可暫停／恢復的 runner 契約，處理音訊游標、客體時鐘與恢復後輸入，才能標示「已暫停」。

驗收：選單開啟期間角色與計時不前進；恢復無音訊爆量、時間跳躍或卡鍵。Esc 等鍵目前也可能是客體軟鍵，不能無條件改為主機選單。

### 5. P2：手機預設控制盤不適合所有 Pocket PC 遊戲

Android `activity_game.xml` 的固定配置同時放方向、中央動作、1／2、A／B／C 與 TURBO；直向需為控制區保留高度，橫向則會疊在畫面上。預設透明度為 100%。EQ 以觸控筆為主，常不需要整套按鍵。部分按鍵為 44 dp、TURBO 高 36 dp，卡片更多選單只有 32 dp；密集排列下值得擴大觸控範圍並進行實機檢查。

PPSSPP 提供按鍵重映射、觸控布局移動、透明度、閒置自動隱藏與拖移方向盤等選項，可參考它將控制布局變成可調整偏好的方式。[官方文件](https://www.ppsspp.org/docs/settings/controls/)

建議先做三個簡單預設：觸控筆優先、方向＋動作鍵、完整 Pocket PC。每遊戲記憶選擇，遊玩中一鍵切換顯示；連接手把可選擇自動隱藏。接著才加入移動／縮放按鍵與安全區調整。為低解析度遊戲提供可選局部放大操作，保留原始 stylus 座標與點擊／拖曳語意。

驗收：直／橫向、瀏海與系統手勢區不遮住必要按鍵；EQ 的右上角小按鈕可穩定點擊；隱藏控制盤後仍能開選單。不可改動客體按鈕 hitbox 來掩蓋問題。

### 6. P2：每遊戲操作配置與文字輸入不足

Windows 已有全域 keybinding 編輯；Android 的硬體鍵／手把對應主要固定在 `GameActivity`；Web 多數對應亦寫死。Android 個別遊戲設定沒有控制布局／按鍵重映射項目。Windows 遊玩頁的鍵盤處理主要轉送已綁定虛擬按鍵，不能當作完整 CE 文字輸入方案。

RetroArch 將主機控制器配置與每遊戲重映射分開，也提供直接鍵盤輸入時的焦點模式，避免選單快捷鍵搶走客體文字。[官方文件](https://docs.libretro.com/guides/input-and-controls/)

建議：共用控制配置資料模型，設定優先順序為產品預設、全域、個別遊戲覆寫。操作頁可「恢復此遊戲預設」，不影響其他遊戲。客體文字輸入與遊戲動作分開：提供叫出鍵盤／文字模式，並清楚標示目前輸入目的地。按鍵標籤可顯示實際功能，但沒有已驗證 profile 時維持 CE 通用名稱。

驗收：修改 EQ 的配置不影響其他遊戲；外接手把、觸控與鍵盤同時使用不互相取消；姓名與註冊欄位可以輸入、刪除及切換焦點。

### 7. P2：設定太早要求使用者理解模擬器內部

Windows 與 Android 個別設定直接顯示 CPU、max slices、instructions per slice、halt on unimplemented；Android CPU 選項目前仍是 Stub／Unicorn，未對應發布版 Interpreter。共用設定的 FPS 與 backend log 預設開啟。這些資訊對診斷有幫助，但一般遊玩需要的是操作、畫面、聲音與進度。

建議：普通頁只保留上述玩家選項；CPU 自動選擇，將 slice／追蹤等放進「進階診斷」。提供可複製診斷摘要，顯示實際使用核心而非只列 requested preference。FPS、backend log 預設不占遊戲畫面，可在選單啟用。

這不建議單純將設定文字改名；需要共用核心回報實際能力，才不會把不同 CPU 的功能落差藏起來。

### 8. P2／P3：遊戲庫名稱辨識、搜尋與狀態回饋仍可簡化

Android 卡片名稱最多兩行，既有 EQ 畫面中常見的 EverQuest 前綴佔掉主要辨識空間；Publisher 對三部區分幫助有限。Windows 與 Android 目前是基本卡片清單，未見最近遊玩／收藏／遊戲庫搜尋流程。Web 的搜尋主要位於線上程式目錄，不能等同已匯入遊戲庫有相同能力。

建議：保留原始正式名稱，但容許本機顯示別名與副標題，如「EQ I」「EQ II：Qeynos」「EQ III：Faydwer」。顯示最近遊玩、是否有進度備份；先做名稱搜尋及最近遊玩，再做收藏／列表切換。主動作叫「開始遊戲」；只有實作即時恢復狀態時才叫「繼續上次畫面」。載入期間立刻停用重複啟動，顯示可理解的階段和錯誤處置入口。

Web 的 `.pad` 目前 `aria-hidden=true`，互動鍵為 div；Android 部分控制標籤僅為字母／符號。需補上語意、可讀名稱與焦點流程。主機選單的可存取性改善不能宣稱遊戲 framebuffer 已支援螢幕閱讀器。

## 建議操作結構

遊戲庫：搜尋／最近遊玩 → 遊戲卡片 → 開始遊戲。卡片更多選單收納個別設定、備份／還原進度與移除。安全匯入及音效補充沿用單一匯入入口，由內容辨識決定動作。

遊玩：以原始遊戲畫面為主，保留一個穩定可達的模擬器選單入口。選單收納操作、顯示、音量與進度備份；進階診斷再展開。每個平台保留符合主機習慣的外觀，但使用一致名稱及行為契約。

PocketHLE 模擬的是帶觸控筆的 CE 程式，不能直接搬一套 PSP／主機按鍵面板。觸控筆優先、文字輸入與每遊戲布局比增加通用按鍵更有價值。

## 實作順序與驗收邊界

| 階段 | 工作 | 完成條件 |
| --- | --- | --- |
| 第一批 | 同遊戲更新保留進度、Web 同步等待／輸入訂閱清理、退出及備份文字 | 無靜默清除、排隊同步不提前返回、十次重開無累積輸入 |
| 第二批 | 共用暫停契約與三平台遊戲中選單 | 暫停真正停止客體前進，恢復無音訊／時鐘／輸入異常 |
| 第三批 | 觸控筆預設、簡化按鍵盤、每遊戲控制配置、局部放大 | EQ 小按鈕可短點、直橫向不遮擋、配置互不污染 |
| 第四批 | 搜尋、最近遊玩、別名、設定分層、可存取性 | 新使用者可在不理解 CPU／slice 的情況下完成匯入、遊玩、退出及備份 |

即時存檔、倒帶與任意位置續玩列為獨立核心專案。這些需要 CPU、記憶體、HLE 物件、worker、音訊、VFS 及 registry 的一致快照；目前 ZIP 備份不具備此能力。應先把原生進度保存、退出與恢復契約做好，再排這些功能。

後續操作測試應涵蓋：首次匯入、同遊戲安全更新、EQ 三部短點／拖曳／小目標、進度備份還原、切換背景／旋轉／失焦、同頁多次開關、鍵盤文字與手把同時使用。過往音訊與進世界測試通過，不能替代這些 UX 驗收。
