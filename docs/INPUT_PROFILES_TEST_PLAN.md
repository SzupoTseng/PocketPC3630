本文件定義完整操作方案與測試，不代表所有介面與案例已完成。2026-11-08 Web 首版已提供七種介紹預覽、其中六種的可見按鍵／鍵盤設定，以及部分配置隔離、生命週期測試，見 [實測紀錄](../proof/library-ui/README.md)；硬體鍵路由、任意重映射及原生介面仍待實作。既有啟動、世界畫面、音訊證據維持原有範圍。測試軟體須使用本機合法持有的指定版本；沒有素材、無法啟動或缺少平台能力時，記錄原因，不能填通過。

## 可選操作方案

使用者在「個別軟體設定 → 操作方式」選擇方案，遊戲中選單也能切換。新軟體預設繼承全域設定；已驗證的軟體可顯示推薦方案，但不強制套用。每個方案都可進入自訂，不必為了保留一個快捷鍵而顯示整套控制盤。

| 編號 | 方案 | 預設顯示／輸入 | 可選調整 | 適用情境 |
| --- | --- | --- | --- | --- |
| OP-01 | 觸控筆優先 | 畫面直接點擊／拖曳，隱藏大型按鍵盤 | 精簡快捷列、按住、局部放大 | EQ、消除／紙牌、計算機 |
| OP-02 | 方向＋動作鍵 | 方向盤＋中央動作鍵，仍可點畫面 | 增加必要軟鍵、左右手布局、方向滑移 | JumpyBall 等動作遊戲 |
| OP-03 | 完整 Pocket PC | 方向、中央動作、軟鍵 1／2、A／B／C | 逐鍵隱藏／映射、透明度、位置、大小 | 需要多個硬體鍵的舊軟體 |
| OP-04 | 文字／閱讀 | 觸控筆、叫出文字鍵盤、可選翻頁／導覽列 | 原樣文字輸入、Tab／Backspace、複製貼上能力 | 閱讀器、編輯器、姓名欄位 |
| OP-05 | 滑鼠＋鍵盤 | 實體鍵盤映射與滑鼠指標，隱藏觸控盤 | 絕對位置／相對移動、靈敏度、游標擷取 | Quake 類與桌面遊玩 |
| OP-06 | 自訂 | 從任一方案複製，只啟用所需控制 | 混合來源、快捷列、各方向布局 | 個別軟體特殊需求 |
| OP-07 | 裝置面板（Device Emulator 風格） | 裝置外框中的螢幕＋依機型定義的方向／中央鍵／硬體應用鍵 | 機型面板、顯示外框或精簡硬體列、主機快捷鍵／手把對應 | 需要原裝置硬體鍵的 CE 軟體與相容性對照 |

這是可調整的起點，不是互斥的硬體限制。額外輸入來源、布局與文字焦點獨立設定：

- **手把：**關閉／啟用選定裝置；逐鍵映射、死區、方向軸及主機選單快捷鍵。可與任一方案並用；連接後可選自動隱藏觸控盤。
- **觸控／滑鼠：**CE 觸控筆預設使用絕對座標。相對移動與游標擷取須由軟體及前端支援，不能將滑鼠移動直接當作 CE 原生相對滑鼠已實作。
- **文字：**操作映射與原樣文字模式分開。未支援的 IME、貼上或字元集明確標示能力限制，不吞字或假回成功。
- **布局：**每個軟體可分開保存直向／橫向布局，調整按鍵顯示、大小、位置、透明度、左右手；旋轉呈現不自動修改客體解析度。
- **主機選單：**永遠有可達入口；主機快捷鍵與 CE 軟鍵可分開配置，禁止隱藏控制盤後無法返回。
- **連發：**僅作明確選用的動作，預設關閉；不得把一般按住誤作連發，文字模式停用連發。

### OP-07 裝置面板：外觀與按鈕行為一起定義

這一項參考 Microsoft Device Emulator 以 skin／按鈕熱區呈現裝置的方式，與單純顯示遊戲 A／B／C 按鍵不同。使用者可逐軟體選擇「使用裝置按鈕」或維持遊戲映射；同一硬體鍵的螢幕熱區、鍵盤快捷鍵與手把映射共用一個裝置語意。

| 控制 | 規劃行為 | 參照限制 |
| --- | --- | --- |
| 四方向 | 分別處理按下、按住、放開；斜向／組合由實際面板能力決定 | 依指定 skin／映像量測，不假定所有裝置都支持同樣組合 |
| 中央動作鍵 | 使用裝置定義的 Action 行為 | 區分 `VK_ACTION`、`VK_RETURN` 與 GAPI 確認鍵；有無額外事件由 probe 確認 |
| 硬體應用鍵 | 依面板提供 App1～AppN，需對照 CE 硬體鍵及訊息路由 | `VK_APP1～VK_APP6` 不等於固定 A／B／C；日曆／聯絡人等圖示及功能須依映像驗證，不硬編成所有機型都相同 |
| 左右軟鍵／其他機型鍵 | 只在面板參照確實提供時顯示；短按、長按行為分開 | Pocket PC 2003、不同 Windows Mobile 版本及 OEM 配置不能共用未驗證的鍵碼表 |
| 螢幕觸控筆 | 外框內螢幕區才映射客體絕對座標 | 點裝置按鈕熱區不得同時變成客體螢幕點擊 |
| Power／Reset | 有獨立能力與操作名稱，未實作時停用並說明 | 不能以靜音當作 CE suspend，不能以主機快捷鍵或普通客體按鍵冒充 reset；重新啟動須遵守進度保護契約 |

資料模型另列 `device_profile_id`、裝置／OS 映像識別、skin／映射版本、螢幕 viewport、按鈕熱區、按下／放開／重複策略、來源到裝置按鈕及裝置到客體事件的對應。螢幕縮放、旋轉時外框與熱區同步換算；可隱藏外框但保留相同按鈕語意。採專案可維護的描述格式，不先承諾能直接匯入所有 Microsoft skin XML。

現有程式 `GuestButton` 把 A／B／C 映到 Ctrl／Space／Shift 等主機輸入，GAPI 另有 `GXGetDefaultKeys` 及目前 `0xD1～0xD4` 的契約；這些是既有相容性路徑，不能為了加入硬體應用鍵而全域改碼。現有 `SHSetAppKeyWndAssoc` 出現在 AYGSHELL 登記清單，也不能據此認定硬體鍵路由已完整實作。需獨立測試一般 WM_KEY 訊息、GetKeyState／GetAsyncKeyState、GAPI 與 shell／hotkey 註冊路由。

PocketHLE 是 HLE，送出 App1 不代表已有 CE 桌面或日曆程式可啟動。按鈕輸入、程式註冊接收與 shell 應用啟動分開報告；沒實作的 OS 功能明確列能力缺口。Device Emulator 參照也不等於 iPAQ 3630 真機，面板名稱必須標示實際參照來源。

## 設定與切換規則

1. 共用 Rust 設定保存穩定軟體 id、方案 id／版本、控制到 CE 語意的映射；繼承順序為產品預設 → 全域 → 此軟體覆寫。
2. 平台專屬按鍵碼、手把裝置及布局另列在平台覆寫；不將 Android 實體像素座標直接套到 Web／Windows。
3. 畫面顯示「繼承全域」或「此軟體自訂」，並提供「只恢復此軟體預設」。推薦方案要有版本／架構匹配與驗證紀錄；未知軟體保留可選入口，不以名稱猜測強制綁定。
4. 切換方案前釋放舊來源的按鍵、stylus、連發與延遲回呼，再套用新配置；不得重開客體或修改遊戲進度。
5. 平台不支援的輸入選項停用並說明原因，不顯示成可用。不同裝置都要有退路，不依賴外接手把才能開選單。
6. 控制配置納入設定遷移與安全更新。既有進度 ZIP 是否包含配置須另行定義；未擴充格式前，不宣稱備份 ZIP 會搬移操作配置。共享配置匯入不得覆寫進度或帶入本機裝置識別資訊。

## 每次測試的共同條件

測試維度記為 `軟體版本／EXE 雜湊 × 平台／CPU × 方案 × 實際輸入來源 × 方向`；各組合獨立記錄。每套先驗主要方案，再測表列替代方案與方案切換，不能用一次啟動代表全部通過。

| 案例 | 操作步驟 | 通過條件 |
| --- | --- | --- |
| CT-01 設定獨立 | A 選方案並改一個按鍵；B 選另一方案；關閉並重啟兩者 | A／B 各自保留、互不污染；恢復 A 不影響 B 或全域 |
| CT-02 短點 | 在可重複、無副作用目標各做 50／100／150／250／500 ms 點擊，每種 20 次；正常與低效能條件分開 | 記錄送出／客體接收／畫面回應；每次有效點擊僅觸發一次，正常 100～250 ms 不漏接；50 ms 結果保留並調查。長按不能替代短點驗收 |
| CT-03 按住與同時按 | 四方向各按住 3 秒；方向＋動作 3 秒；同鍵由鍵盤及虛擬鍵同時持有，依序放開 | 按住持續有效，最後來源放開才產生 KeyUp；一般動作無非預期連發 |
| CT-04 指標與取消 | 點四角與中央、拖曳後滑出邊界、取消觸控、多指干擾 | 座標正確，取消有 release；單一 CE stylus 不因第二根手指突然跳位 |
| CT-05 方案切換 | 按住方向／拖曳時改方案；顯示／隱藏控制盤；原樣文字模式來回切換 | 客體不重啟、不殘留按住／連發／舊回呼，進度不變 |
| CT-06 方向與放大 | 直向、橫向、旋轉呈現、全螢幕、局部放大後各點同一目標 | 座標與圖片一致，必要操作不被遮住；客體解析度沒有意外改變 |
| CT-07 背景／失焦 | 按住時切視窗／分頁、Android Home／恢復，重複 5 次 | 無卡鍵；恢復行為符合已實作的暫停政策，不以靜音當作暫停 |
| CT-08 外接裝置 | 手把連接、持鍵斷線、重接；滑鼠／鍵盤／觸控混用 | 斷線釋放該來源，其他來源可繼續；有選單退路，裝置重接不套錯配置 |
| CT-09 文字與快捷鍵 | 在可編輯欄位輸入 `Ab09`、空白、退格，Tab／方向移動焦點；支援時測中文組字 | 文字只進入正確欄位、不變成遊戲動作，主機選單不被誤觸；未支援項明確記錄 |
| CT-10 重開與錯誤 | 同頁／同 app 開關同一軟體 10 次，再切換不同解析度軟體；注入配置讀寫失敗 | 事件／計時器不累積，映射與座標無舊值；寫入失敗可知且不假報保存 |
| CT-11 原生進度 | 依軟體正常保存後退出，新程序讀回，再備份／還原 | 進度可還原；操作方案也依設定契約保留，兩者不混為即時存檔 |
| CT-12 選單／暫停 | 用觸控、鍵盤、手把開選單、繼續、返回；隱藏控制盤時再測 | 入口可達；UI-06 完成後才驗真正暫停及客體時間；缺能力時列待實作，不填通過 |

CT-02 若軟體有已確認的輪詢頻率限制，先用相同版本裝置參照量測並記錄例外，不能任意降低門檻。全螢幕／局部放大／IME／手把等未實作能力，記「待實作」；平台本質不適用則記「不適用」及理由。

| APP-12 裝置硬體鍵 probe／指定 CE 軟體 | OP-07 → OP-03／OP-06 | 固定 Device Emulator 的映像及 skin → 量測硬體鍵 → 同一 probe 在 PocketHLE 重播 → 選一套確實使用該硬體鍵的軟體走完整操作 | 先跑 DE-01～08；APP-01～11 需要硬體鍵者各補 OP-07 結果，不能只驗面板會亮或共用 APP-11 的窗口測試結果 |

APP-01～11 都要執行 CT-01、CT-04～07、CT-10；有相應動作的軟體再執行 CT-02／03／08／09／11／12。每一項無法執行時寫明原因；不能用空白代表不適用。算式、搜尋內容與測試文件使用自製、不敏感資料。

以下全部待測。既有 `tools/wince-window-test` 與 `tools/wince-dialog-test` 有 Pocket PC 2003 參照，但不是完整硬體輸入 trace；需擴充或另建 input probe，不能沿用它們當作按鈕已通過。

| 案例 | 逐項步驟 | 通過條件／證據 |
| --- | --- | --- |
| DE-01 參照固定 | 記錄 Device Emulator 版本、ROM／OS、skin XML 及圖像雜湊、方向、主機快捷鍵、裝置按鈕設定；盤點實際按鈕 | 每個面板可追溯，不把不同映像／OEM 的結果混用；缺參照則阻塞 |
| DE-02 每個硬體鍵 | 在 probe 內將方向、中央鍵、每個 App 鍵、存在的軟鍵各短按 20 次，先點 skin，再用主機快捷鍵；PocketHLE 面板／鍵盤／手把分別重跑 | 比對完整 Down／Up、VK、掃描碼、lParam transition／repeat、接收窗口；同動作不重複、不漏掉必要事件 |
| DE-03 中央鍵與 GAPI | 一般窗口及實際呼叫 GXGetDefaultKeys 的程式分開按中央鍵；記錄查詢結果、輪詢狀態與訊息 | Action／Return／GAPI 動作與指定參照一致；加入 OP-07 不破壞既有 OP-02／03 與遊戲確認鍵 |
| DE-04 長按／重複 | 每鍵按住 3 秒，記錄重複延遲／間隔；支援長按動作的軟體另驗短按／長按 | 與參照行為吻合；忽略主機排程造成的微小時間差並記量測範圍，不額外啟用遊戲連發 |
| DE-05 組合／多來源 | 方向＋中央、方向＋App 鍵、兩 App 鍵；同鍵由鍵盤及面板同時持有，再依序釋放 | 支援組合依參照辨識；最後來源釋放才 KeyUp，無全鍵誤釋放或卡鍵；不支援組合記錄限制 |
| DE-06 應用鍵接收 | probe 驗證未註冊、已關聯窗口、解除關聯及失焦情形；只在參照確實使用時比較 hotkey 路徑 | `SHSetAppKeyWndAssoc` 等實際用到的路由與參照一致，未實作 shell 啟動獨立標記，不以成功 stub 代替 |
| DE-07 外框／旋轉 | 全螢幕、面板縮放、直橫向、顯示／隱藏外框；逐個熱區點擊並拖離、取消 | 面板鍵不落入畫面，viewport 四角座標正確，按鈕動畫與釋放一致；旋轉後重測 DE-02 |
| DE-08 生命週期／系統鍵 | 持鍵失焦、背景、切方案、退出重開；Power／Reset 僅在明確實作時分別測試 | 無殘留狀態；Power 的客體狀態與 Reset 的重新啟動語意可驗證，不假報支持，存檔按契約保護 |

完成 probe 對照後，逐套執行 APP-01～12 中適用的真實軟體流程；每個實際前端都要驗面板、鍵盤及可用手把來源，不能以 Windows Device Emulator 的按鈕測試代替 Web／Android UI 驗收。

## 平台與執行核心矩陣

| 測試組 | 環境／輸入來源 | 必測事項 | 初始狀態 |
| --- | --- | --- | --- |
| WIN-GUI | Windows egui 實際建置核心；滑鼠、鍵盤、支援時手把 | 遊戲庫到遊戲中完整流程、F11／失焦、文字焦點、控制布局 | 未測 |
| WEB-DESKTOP | 固定版本 Chrome／Edge；WASM 實際核心；滑鼠鍵盤 | 同頁十次重開、IndexedDB 保存、文字焦點、支援時 Gamepad／Pointer Lock | 未測 |
| WEB-TOUCH | Android Chrome 真實觸控；其他目標瀏覽器另列版本 | 多指取消、軟鍵盤、安全區、橫直向、背景恢復、支援時外接裝置 | 未測 |
| ANDROID-EMU-U | 專用 x86_64 模擬器、Unicorn APK | 可重複輸入注入與事件紀錄，主機點擊／客體接收分開 | 未測 |
| ANDROID-EMU-I | 同一隔離測試環境、Interpreter APK | 同版素材與方案重跑，不能沿用 Unicorn 結果 | 未測 |

Windows CLI 可輔助定位客體輸入，不能代替 WIN-GUI。桌面 CDP 注入不能代替 WEB-TOUCH 或手機手感；Android 模擬器不能代替 ARM64 實機。其他瀏覽器／平台只有實際納入後才聲稱支持該配置。

## 執行順序與結果格式

1. 先完成 UI-11 的設定模型／能力回報及 UI-04 輸入生命週期，確認 CT-01／03／05／10；暫停測試另依賴 UI-06。
2. 以 APP-11 probe、APP-08 計算機建立可觀察的點擊／按鍵基線；UI-19／20 的裝置面板另外先跑 APP-12 及 DE-01～08，再驗 APP-01～03，逐部留下結果。
3. 驗 APP-04～07，涵蓋 WVGA、連續動作、精確指標與複合按鍵。
4. 驗 APP-09～10 的閱讀／文字流程；啟動或素材阻塞單獨記錄，不消失於總表。
5. 每套的主要方案通過後再跑替代方案／手把；最後跑真實觸控、實機與跨軟體配置切換。

每個案例至少記：案例 id、軟體 id／版本／架構／EXE 雜湊、前端與產物雜湊、實際 CPU、OS／瀏覽器／裝置、方案及配置版本、輸入來源、方向、前置條件、步驟、期望、實際結果、失敗次數／總次數、日誌／截圖／必要錄影，以及獨立存檔目錄。測試不得改動使用者唯一進度。

狀態只用：**未測、待實作、通過、失敗、阻塞、不適用（附原因）**。Web 首版的局部測試另外記錄，不代表 APP-01～12 或各平台完整案例已通過。任何必測項未測／失敗／阻塞時，不將整套軟體標為「操作完整」。素材不足、相容性失敗、輸入失敗及前端能力不足分開歸因。

新加入的每套軟體都要建立自己的 APP 測試單，包含推薦與替代方案、實際可用的操作、保存行為及平台結果。`docs/COMPATIBILITY.md` 的啟動結果可用來選測試素材，不能直接轉成操作驗收通過。
